# Phase 1 review (EjectKit core) — 2026-10-21

> Historical document: written while the app was still called DriveUser (CLI `drivectl`, env `DRIVEUSER_DEBUG`); it was renamed Ejectable (`ejectctl`, `EJECTABLE_DEBUG`) before release. File and line references are as of the review.

Reviewer: Opus 5.5, read-only audit against PLAN §4b. Totals: 0 critical, 1 high, 7 medium, 21 low, 2 questions. Verdict: soft-eject core sound (S5 guard runs twice before any DA request, dryRun sends nothing, force never implicit, DA callbacks balanced, 27/27 tests). Line numbers are as of the review; re-locate by description.

## Fix before UI relies on it (pass A)
- **HIGH** `HolderScanner.swift:76` `uniqueTargets()` takes whatever mount `statfs` reports for a path, never checks the path is itself a mount point. A leftover `/Volumes/X` dir (phase-3 scan racing the unmount), a subdirectory, or the `/Volumes/Macintosh HD -> /` symlink on this Mac turns the target into `/System/Volumes/Data` or `/` → dozens of unrelated apps listed as holders, Quit All would offer to quit them. Fix: skip target unless `f_mntonname == path`; reject `MNT_ROOTFS` and `/System/Volumes` targets.
- **MED** `HolderResolver.swift:46` daemon-name / system-prefix rules only applied in the CLI branch. A listed daemon with an NSRunningApplication, or one inside a `.app` (e.g. `postgres` under Postgres.app or an NLE bundle → `.helper`), becomes quittable (S4). Fix: evaluate daemon rule before the app/helper classification.
- **MED** `DiskTopology.swift:102` `externalVolumes()` uses `FileManager.mountedVolumeURLs` + resource values and `volumeInfo(url:)` calls `statfs(path)` — both stat SMB synchronously; offline NAS after sleep blocks for seconds/indefinitely → beachball if on main. Fix: build list from `mountTable()` (`MNT_NOWAIT`), never stat non-local mounts.
- **MED** `SystemState.swift:17` S2 gates fail open: if `tmutil` fails/times out, `timeMachineBackupRunning()` → false and `timeMachineDestinations()` → [] so Force Eject enabled with TM state unknown. Fix: return `Bool?`/throw; UI disables Force on nil. (SafetyGate in phase 2 must adopt this.)

## Fix before phase 6 (real drive) (pass B)
- **MED/Q** `Ejector.swift:228` The test SSD (a USB SSD) reports `Ejectable=0`. If `DADiskEject` dissents after all unmounts succeeded, result is `.failed(step: .eject)` though everything is flushed and unmounted; UI would invite retry/Force. Fix: distinct `.unmountedNotEjected` result ("safe to disconnect"); verify in phase 6.
- **MED** `DiskTopology.swift:212` "last Whole IOMedia = outermost" assumes a single-parent chain. AppleRAID/SoftRAID sets (ThunderBay-style, common for editors), Fusion, multi-store APFS have several Whole ancestors → arbitrary member picked; S5 checks only that member; `DADiskEject` hits one RAID member. Fix: collect all Whole ancestors; refuse `.multiMemberDisk` when > 1 until tested.
- **MED** `drivectl/main.swift:100` `eject --force --real` force-unmounts a real disk with no S2 gates (no scan, no TM check, no confirmation). Fix: scan first, refuse on writers/mappings/running backup unless extra flag; y/N prompt.
- **MED** `HolderScanner.swift:125` kernel `PROC_PIDREGIONPATHINFO3` walk stops with EINVAL (same as "no match") at the first mapped vnode whose `vnode_getwithvid`/`getattr` fails, and getattr runs on every mapped vnode. A process still mapping a file from a previously force-ejected volume or an offline SMB share → false "no mmap" or stalled scan. Missed mmap holder lets Force through → SIGBUS in the NLE. Fix: when probe fails for GUI apps, fall back to a `PROC_PIDREGIONPATHINFO2` walk; scans get a deadline and an `incomplete` flag (UI: disable Force when incomplete).
- **LOW** `Ejector.swift:154` Darwin `sync()` doesn't wait; forced dounmount skips VFS_SYNC. Fix: `sync_volume_np(path, SYNC_VOLUME_FULLSYNC | SYNC_VOLUME_WAIT)` per volume before forced unmount (unistd.h).
- **MED** `SafetyTests.swift:52` forged snapshot is refused by the identity check, so the fresh-state S5 check at `Ejector.swift:152` is never reached by any test; deleting it keeps the suite green. Fix: forge with the root disk's real model/size/appearanceTime/isVirtual but `isInternal=false`, `volumes=[]`; assert `.refused(.internalDisk)`.

## Lows (do in pass B unless trivial)
- `ActionLog.swift:27` paths logged to os_log `.public`; file 0644, never rotated. Fix: `.private` for paths in os_log, file 0600, cap/rotate.
- `DiskTopology.swift:146` `bsdName` only when `f_mntfromname` starts with `/dev/disk`; APFS snapshot / TM mounts (`com.apple.TimeMachine…@/dev/diskNsM`) omitted from `volumes` → skip S5/S8/scan but Whole unmount still takes them. Fix: parse `@/dev/disk…` suffix.
- `DiskTopology.swift:182` `|| model == "Disk Image"` lets a real USB device with that product string pass `.diskImagesOnly`. Fix: drop the model clause (fixtures report protocol "Virtual Interface").
- `DiskTopology.swift:186` **Q**: built-in SDXC readers and some Thunderbolt NVMe enclosures report `DADeviceInternal`/`volumeIsInternal = true` → refused and hidden. Decision: use IOKit `Physical Interconnect Location == "External"` as the primary external test (diskutil shows "Device Location: External" for the test SSD); fall back to `DADeviceInternal == false` when absent. Root/internal-volume checks stay.
- `Ejector.swift:148` identity check doesn't compare `fresh.volumePaths` with snapshot; a volume mounted after the user confirmed Force is force-unmounted without consent (S2/S8). Fix: when `force`, refuse `.diskChanged` if volume sets differ.
- `Ejector.swift:153` dry-run attempts logged as real `[force-eject] attempt` lines. Fix: tag dry-run in log.
- `Ejector.swift:162` network path has no `/Volumes/` prefix guard (NFS home under /Users could be unmounted); completion runs on FileManager's queue, breaking the "completions on `queue`" contract. Fix: prefix check + `queue.async { completion(r) }`.
- `Ejector.swift:224` physical disk and containers re-created by BSD name after unmounts that can take 10 s+; no identity re-check; unplug + BSD-name reuse → different disk. Fix: compare `DAAppearanceTime` before each `DADiskUnmount`/`DADiskEject`.
- `Ejector.swift:242` `kDAReturnBusy` (0xF8DA0002) and `kDAReturnExclusiveAccess` map to `.failed` → holder flow never offered. Fix: treat as busy, pid nil.
- `Holder.swift:103` S6 fails open: start time recorded but `LibProc.startTime(pid)` now nil → returns true. Fix: `guard let now … else { return false }`.
- `Holder.swift:115` `parentRunningApplication()` no S6/liveness check; returns first instance matching bundle URL. Fix: require `isSameProcess()` first.
- `Holder.swift:131` `isClear` true when no target resolved (every statfs failed) → never-scanned volume reads "clear". Fix: expose `scannedTargets`; empty = unknown, not clear.
- `HolderScanner.swift:37` exe path + start time captured after `concurrentPerform`, not at inspection; recycled pid gets old reasons with new identity. Fix: read start time inside `inspect()` before vnode calls; drop hit if changed by resolve time.
- `HolderScanner.swift:129` (+178) `writable = pri_protection & VM_PROT_WRITE` ignores `pri_share_mode`; COW private mappings (`__DATA` of an app/plugin run from the drive) flagged mmap(w) → false writer disables Force. Fix: writable only for `SM_SHARED`, `SM_TRUESHARED`, `SM_SHARED_ALIASED`.
- `HolderScanner.swift:142` + `LibProc.swift:36` `PROC_PIDLISTFDS` / `proc_listallpids` not retried when result fills buffer → silent truncation. Fix: if result == capacity, double and repeat.
- `Tests/EjectKitTests/Fixture.swift:55` state file without `mount` defaults to "" → `physicalDisk(forVolume: "")` resolves cwd's volume. Fix: XCTSkip unless mount starts with `/Volumes/DUTEST`.
- `SafetyTests.swift:72` (+105) refusal tests use a live `Ejector()`; a regressed identity check would soft-eject whatever image now holds that BSD name. Fix: `Ejector(dryRun: true)`; add dryRun-on-fixture test asserting target still mounted and count == 1.
- `Tests/fixtures/make-busy-volume.sh:25` `DUTEST[A-Z0-9_]*` glob lets trailing `*` match `/` and `..`. Fix: `DUTEST*[!A-Z0-9_]*) die ;; DUTEST?*) ;;`.
- `make-busy-volume.sh:55` pid-reuse check compares comm basename only; stale state file could kill an unrelated user `tail`/`sleep`. Fix: record `ps -o lstart=` at spawn, require match.
- `make-busy-volume.sh:81` `attached_device` then `hdiutil detach [-force] $dev` is check-then-act. Fix: re-check `hdiutil info` maps `$dev` → `$img` immediately before each detach; no `-force` unless that passes.
- `PLAN.md` S2 said `O_WRONLY|O_RDWR`; code (FWRITE) was right. PLAN fixed 2026-10-21.

## Verified OK by reviewer
fsid64/st_dev probe per filesystem incl. exFAT via FSKit; `& FWRITE` writer detection; `O_EVTONLY` skip; bounded C-string decoding; EPERM → denied; no `concurrentPerform` races (per-worker buffers, locked sink); every `passRetained` balanced by `takeRetainedValue`; completion exactly once on every path; `status & 0x3fff == EBUSY` precedence correct; `"DAProcessID"` extraction; pid 0 → nil; start time from `sysctl KERN_PROC_PID p_starttime`, compared within 1 ms; `@unchecked Sendable` / `nonisolated(unsafe)` uses sound; no process spawning on the scan path.
